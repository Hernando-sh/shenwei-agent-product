# Release w2 · 工具工程与受控业务执行

## 启动方式

```bash
cd shenwei-agent-product && cp .env.example .env    # 填 DASHSCOPE_API_KEY
make sync && make test                               # 离线：135 条单测，FakeERP / FakeKnowledge / ScriptedConfirm / FakeMcpClient
make erp                                             # 终端 1：模拟 ERP 9100
make chat TEXT="给雅加达客户报 2 台 X200。"           # 终端 2：真实模型 + ERP；写台账前在终端里确认（y / n / JSON 改参数）
```

知识服务（9200）与 SCRM（9300）是课程共享实例（`S6/环境/`，`docker compose up -d`）；本周代码只读知识服务。

## 必要配置

`.env`：`DASHSCOPE_API_KEY`（真实模型）、`AGENT_MODEL`（默认 qwen-plus）、`ERP_BASE_URL`（默认 localhost:9100）、`ERP_API_KEY`（east-demo-key）、`KB_BASE_URL`（默认 localhost:9200）、`AGENT_RUNS_DIR`（默认 runs，不入库）。

## 案例命令

```bash
make chat TEXT="给雅加达客户报 2 台 X200。"                 # 主案例：客户 → 算价草案 → 终端确认 → 写台账 → 答复报价号
make chat TEXT="杜塞尔多夫客户要 1 台 X300，报个价。"         # 逾期客户：规则拦下，不出草案
make chat TEXT="给雅加达报 2 台 X200，单价按 280 美金。"      # 业务员给金额：280 进不了任何请求
make chat ARGS="--mode auto" TEXT="…"                       # 自动模式：报价台账写入仍确认
make chat ARGS="--source mcp" TEXT="查一下 X200 的规格和当前库存交期"   # 两个只读工具经 MCP 服务
make chat-offline TEXT="给雅加达客户报 2 台 X200"            # 离线脚本：走真实的确认环节，不需要 Key 和 ERP
make replay ID=<会话id>                                     # 只读回放
ERP_BASE_URL=http://localhost:9177 uv run --project apps/agent-python python scripts/smoke_w2.py   # 十条冒烟（私有 ERP）
ERP_BASE_URL=http://localhost:9177 ERP_WRITE_BASE_URL=http://localhost:9177 make integration        # 契约 + 写契约 + MCP 集成
uv run --project apps/agent-python python scripts/release_check.py
```

私有 ERP 实例：`ERP_PORT=9177 uv run --directory ../../环境/shenwei-erp python -m shenwei_erp`（冒烟与写契约测试会重置它的账本，别指向共享 9100）。

## 新增能力

四个客户 / 回款 / 台账只读工具（空结果 ≠ 不存在，401 ≠ 不存在）；ToolRuntime 单一管线（解析 → 校验 → 策略 → 确认决策 → 执行 → 结果），表驱动策略，本地与 MCP 来源同一策略；知识证据工具（出处 + 版本，空命中不编造）；算价出草案（规则 blocked → credit_hold → overdue → duplicate 由程序在算价前判；草案金额只从 ERP 取；参数没有金额字段，嵌套也拦）；变更集与确认令牌（绑定摘要、10 分钟有效期；同意 / 拒绝 / 改参数）；询问 / 自动模式与 mode.changed；写台账（幂等键 `<run_id>:<operation_id>`、X-Actor、结果未知同键核实一次、操作台账）；业务结果事件 run.outcome；MCP 能力来源（stdio 服务 + 客户端，断开 / 协议错误可区分）；1.9 作业参考实现 get_order。

## 已知限制

确认是终端同步阻塞，没有挂起等人（W6）与跨进程核验（W5）；确认不持久化；并发写（409 idempotency_in_progress）不处理；知识库里没有 ERP 引用的「报价规程 v2026.1」，search_knowledge 对它如实返回空；模型在算价前习惯多查规格与库存（允许，记录）；W2-AC-12m 只有人工判定（W4 判定器）；Q04 类场景模型可能用只读工具自行判定逾期而不调 price_quote（规则结果一致，但没有 run.outcome 事件）；MCP 来源只做了只读两个工具，没有凭据与能力治理（W8）。
